# Data dictionary and provenance

All CSVs are generated from software. There is no imported fab dataset. Seeds index pseudorandom campaigns, not dates or real lots.

| File | Row / main fields | Interpretation |
|---|---|---|
| wafers.csv | tool, campaign, lot, wafer, depth_nm, nonuniformity_pct, cd_error_nm, good | Five rows per lot; metrology and sensor summaries. `truth_age`/`truth_fault` are audit-only simulator fields |
| sensors.csv | one row/tool/lot; measured sensor averages, lots_since_clean, episode, failure_after_lot | Snapshot before post-lot service; episode labels identify intervals between service |
| events.csv | tool, kind, start_s, end_s, duration_s, units, good_units | Non-overlapping per-tool event ledger; clock starts at zero for each tool |
| reliability.csv | tool, operating_h, MTBF_h, MTTR_h, availability, performance, quality, OEE | Derived from event ledger; fractions, not percentages |
| spc_baseline.csv | five columns, 40 rows | Raw ETCH-01 Phase-I subgroup measurements in nm |
| charts.csv | scenario, lot, chart statistics, limits, Boolean alarms | Phase-II evidence with frozen limits; lot index starts at zero |
| challenge_wafers.csv | scenario, lot, wafer, metrology and sensor fields | Raw independent challenge data; nominal seed from metrics.json |
| detection_trials.csv | seed, scenario, chart delay and alarm counts | Blank delay means no post-onset signal, not immediate detection; onset lot 30 |
| matching_calibration.csv | tool, depth_nm | Only these rows estimate offsets |
| matching_confirmation.csv | tool, before/after, depth_nm | Independent confirmation wafers |
| matching.csv | proposed time, mean offsets, confidence bounds, equivalence flags | Clean-state per-tool compensation |
| maintenance_dataset.csv | campaign/tool/episode/lot, measured features, failure_next_5 | Censored end-of-episode futures removed; no truth state |
| maintenance_predictions.csv | held-out campaign/tool/lot, outcome and model probabilities | Used to independently recompute predictive metrics |
| optimization_history.csv | seed, method, evaluation, recipe, loss, best_loss | All budgeted recipe evaluations, not just the best runs |
| optimization_confirmation.csv | recommended recipes plus new stochastic wafer metrics | Nominal, Bayesian and random results per seed |
| metrics.json | computed summaries | Source of reported numbers |
| manifest.json | source hashes, CSV hashes, versions, command and seed | Checksums are for exact run provenance, not proof of physical validation |

The generated report explains denominators and limitations. `scripts/verify_report.py` independently checks hashes and recalculates core metrics. Changing code after a run should cause the source check to fail until new evidence is generated. Reports generated by older source are historical evidence and should not be relabeled as current.
